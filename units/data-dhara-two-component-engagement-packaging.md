## Unit

According to the Data DHARA pathway's account of Nivesh Suvidha (Invest UP), this is a strategic decision from the deployment.

**Decision.** Package every engagement into two components: a reusable technical toolkit, and the non-technical mechanisms (institutional anchoring, coordination, playbook) that make it land.

**Alternative considered.** Not documented in the source

**Why.** The non-technical component is roughly 70% of the value; each implementation should solve a local use case while generating reusable technical assets and non-technical know-how that lowers cost and uncertainty for every subsequent adopter.

**Context.** Nivesh Suvidha's named reusable technical toolkits: a structured, machine-readable government policy/GO knowledge repository; an investor UI toolkit; an open-source code repository deployable by any state or agency; a telemetry/usage-analytics framework.

## Condition

- **Applies when:** Not documented in the source
- **Fails when:** The institution has no willingness to name a nodal owner for data, or the underlying data genuinely doesn't exist yet.

## Before → after

- **Before:** Not documented in the source
- **After:** Four sibling pathways (Delhi vital statistics, Nivesh Suvidha, UPSIDA, data for exports) have emerged from pilots, each paired with a named reusable asset.

## Why it is reusable

The condition tag says when this choice held in the source deployment; the alternative and the before→after show what a different choice would trade away. It is a suggestion from another adoption's lived experience, not a recommendation.
