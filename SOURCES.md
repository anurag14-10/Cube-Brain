# Sources — Cube-Brain

Every system this brain may consult to corroborate an entry. The `id` (the
heading) is what `sources[].system` and `external_refs[].store` must use —
renaming one orphans every reference to it.

## Rules that apply to every source

- **Read-only, always.** Nothing in this brain's workflow writes to the
  diffusion-cube repo, its database, or GitHub. The brain is updated *from*
  them.
- **A probe must confirm data, not connection.** If the probe returns nothing,
  the source is unavailable for this session — say so; do not claim
  corroboration.
- **Say which sources were used.** Silence about a source reads as
  corroboration.

## Registry

### `diffusion_cube_code`

| | |
|---|---|
| **What** | The diffusion-cube git repository: `app/`, `lib/`, `components/`, `content/`, `supabase/migrations/`, `proxy.ts`, `.github/` |
| **Access** | `read` |
| **Cost** | cheap |
| **Probe** | `test -f <repo>/lib/dimensions.ts && git -C <repo> rev-parse HEAD` — a SHA and the file both present |
| **Local path** | `diffusion-cube` beside the brain clone (override with `CUBE_REPO`) |
| **Freshness** | `python3 scripts/check_corpus_drift.py --ref <ref>` after a `git fetch` — read via `git show`, never touching the working tree |

**Trust for:** everything about how the app behaves — routes, access
enforcement, tables, migrations, chat modes, prompts, env var names, module
structure; the framework's structural shape (`lib/dimensions.ts`) and content
(`content/framework.md`); pathway documents in `content/wiki/pathways/` and
`content/library-wiki/pathways/`.

**Do not trust for:** whether a feature is used, who decided something, dates
of decisions, roadmap intent, anything in `published_pathways` (lives in the DB).

| | |

**Do not trust for:** current behaviour where it disagrees with code — the
generated wiki was last refreshed 2026-09-28 and already misses migrations

### `supabase_db`

| | |
|---|---|
| **What** | The live Supabase project (Postgres + Auth + Storage) |
| **Access** | `read` — schema, `published_pathways` metadata and aggregate counts only |
| **Cost** | moderate (needs the project URL and ANON key in the environment; production data) |
| **Probe** | `python3 scripts/probe_published_pathways.py` returns a row count. It reads only slug, title, sector, stage, contributor_org and created_at through the REST API with the anon key (the table's RLS is `select using (true)`), refuses a service-role key, makes GET requests only, and never reads `.env` files |

**Trust for:** which pathways are actually published (`published_pathways`
slugs, titles, sectors, stages), counts.

**Do not trust for / never take:** row contents involving users —
registrations, adoptions, chats, emails. Count, never copy.

## Where authority sits

| Field / question | Ask first | Then |
|---|---|---|
| Framework structure (dimensions, sub-categories, weights, stages, unit types) | `diffusion_cube_code` (`lib/dimensions.ts`) | `raw_documents` |
| Framework content (questions, insight forms, examples) | `diffusion_cube_code` (`content/framework.md`) | `raw_documents` |
| Pathway identity / units | the pathway document in `diffusion_cube_code` | `supabase_db` for DB-only pathways |
| Is a pathway published? | `supabase_db` | `diffusion_cube_code` index.md for in-repo corpus |
| Route / table / migration / env var facts | `diffusion_cube_code` | `diffusion_cube_docs` |
| Why something was built that way | `conversation` | `diffusion_cube_docs` |
| Milestones, requirement status, account expiry | `raw_documents` (charter) | `conversation` |
| Release history | `github_repo` | — |

```yaml
never_automated:
  - pathways.lifecycle    # "published" needs the DB or a person, never inferred from a file existing
  - decisions.status      # whether a decision still stands is a human call
  - risks.status
  - requirements.status   # charter status is set by the program/solution teams
```
